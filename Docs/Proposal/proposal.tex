\section*{The problem}
For our project we will like to create a GUI application,
which will allow user to conveniently add metadata to a .pdf file,
which will signalize that he do not give a permission to process the file with LLM.

\section*{Who cares}
We. And possibly it cares every pdf file author who publish his work.

\section*{How you’ll know it works}
We can check the processed file metadata, if they contain the new added desire
part and persist the original one. However we can not guarantee that LLM's will
respect it.

\section*{Code}
We will start from scratch.

\section*{Who does what}
We assume that the work will be complementary, so that each of us has sufficient awareness of all the important parts of the project.
It is difficult to say what everyone will do if we want to avoid waterfall.

\section*{The biggest risk}

The biggest risk is that other tools try to prevent documents to be use only for
training, not to guard against proceeding it on trained model. And there may be
a good reason for it.

\section*{Motivation}

We want to build such application, because we feel that such tool is missing.
When we were search for this, we firstly found \href{https://pdfa.org/defending-your-pdfs-from-ai-scraping/}{this} technical guide.
However we imagine to found some tools looking similar as for \href{https://www.ilovepdf.com/merge_pdf}{merging pdf}.
We think that the tool to be used by ordinary end users has to look more like the second one than first.

\section*{Possible extension}

Natural extension for this project is to add support for other file types (e.g. epub).
In principle the only requirement to support is new data format is that the new format has to have support for metadata.

\section*{Existing tools}

Based on our initial search and than \href{https://claude.ai/share/48a1993a-63c7-42f8-a55d-212b0818a9cf}{quick check} with Claude,
there are some similar tools.
However they solve slightly different problems or have some limitation
(only paid, platform specific, command line only, \dots ).
